Debug order

  1. Identify the boundary: environment, PyTorch capture, ONNX export, artifact handoff, TensorRT parse/build, runtime binding, or parity.
  2. Prove inputs: path, hash, metadata, shape, dtype, device and versions.
  3. Run the smallest unit: one component, one observation, one engine.
  4. Compare at the nearest tensor boundary: don't wait for the final robot action.
  5. Only then optimize: PTQ, engine reuse, parallel builds, async execution.
