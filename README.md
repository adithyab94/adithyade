# adithya's website

A small [Jekyll](https://jekyllrb.com) site. GitHub Pages builds it for you, so publishing is just pushing.

## Writing a blog post

1. Copy `_drafts/post-template.md` to `_posts/YYYY-MM-DD-short-slug.md`
   (for example `_posts/2026-11-02-tactile-vla.md`). The date in the file name is the publish date,
   and the slug becomes the URL: `/blog/tactile-vla/`.
2. Fill in the front matter at the top (`title`, `subtitle`, `tags`, `links`) and write in Markdown.
3. Put images in `assets/blog/<slug>/` and use them with the figure include:

   ```liquid
   {% include figure.html src="/assets/blog/tactile-vla/rig.jpg" alt="The glove rig" caption="The rig." %}
   ```

   Add `size="wide"` for a figure that breaks out of the text column.
4. Preview locally (below), then commit and push. The post appears on `/blog/` and in the RSS feed
   at `/blog/feed.xml`.

Posts in `_drafts/` are never published. Run the preview with `--drafts` to see them.

### Charts

The charts in the existing posts are inline SVGs generated by `_scripts/charts.py`, so they use the
site's fonts and colours. To add one, write a function there, run `python3 _scripts/charts.py`, and
include it with:

```liquid
{% include chart.html name="my-chart" caption="What to notice." %}
```

A plain PNG through `figure.html` is fine too.

## Offline (photos and personal writing)

`/offline/` holds film rolls, and writing about books, films and anything else. Entries live in `_offline/`.

**Add a roll of film:**

```bash
python3 _scripts/add_roll.py ~/path/to/scans "Roll 03" --camera "Olympus OM-1" --film "Portra 400" --place "Lisbon"
```

It resizes the scans into `assets/offline/roll-03/` (full size + thumbnails) and creates `_offline/roll-03.md`.
Edit that file to add a few lines and optional per-frame captions. The newest roll is the one on the light table.
Delete `_offline/sample-roll.md` and `assets/offline/sample-roll/` once you have a real roll.

**Add writing:** create `_offline/<slug>.md` with `title`, `date`, `kind` (`books`, `films` or `words`) and an
optional `subtitle`. Add `status: in-progress` to list it under "Still marinating" instead of the archive.
Ideas that don't have a page yet go in `_data/marinating.yml`.

## Physical-AI notes

The interactive study notes live in `notes/<slug>/` as plain, self-contained pages (Jekyll copies them
as they are). The list on `/blog/` comes from `_data/notes.yml`: add an entry there to show a new note.

The list is behind a deliberately easy password (the hint is on the page). It's a soft gate:
`localStorage` remembers the unlock, and each note redirects to `/blog/#physical-ai-notes` until then.
Anyone can read the page source, so never put anything private in a note.

The notes are generated by `~/projects/adithya/notes-build/build_notes.py`, kept outside this repo
because it reads local source folders. It restyles each note to the site theme and keeps only code
snippets, not whole files. Re-run it after editing a source, then commit `notes/`.

## Previewing locally

Don't open the `.html` files directly: they are templates, so the browser shows raw front matter and
unstyled text. Run the preview server and open <http://localhost:4000> instead:

```bash
./serve.sh
```

That's the same as this Docker command (no Ruby needed):

```bash
docker run --rm -it -p 4000:4000 -v "$PWD":/srv/jekyll -w /srv/jekyll ruby:3.3 \
  bash -c "bundle install && bundle exec jekyll serve --host 0.0.0.0 --livereload --drafts"
```

Or with Ruby installed: `bundle install`, then `bundle exec jekyll serve`.
Open <http://localhost:4000>.

## Publishing on GitHub Pages

Push the repo to GitHub, then in **Settings → Pages** choose "Deploy from a branch", branch `main`,
folder `/`. If it lives at `https://<user>.github.io/<repo>/`, set `baseurl: "/<repo>"` in
`_config.yml`. Set `url` too, so link previews and the feed have absolute URLs.

## Where things are

| Path | What |
|---|---|
| `index.html`, `work.html`, `about.html`, `blog/index.html` | The pages |
| `_posts/` | Blog posts |
| `_layouts/` | `default` (every page) and `post` (blog posts) |
| `_includes/` | Head, nav, footer, `figure.html`, `chart.html`, and `charts/*.svg` |
| `style.css`, `post.css` | Site styles, and the long-form reading styles |
| `diorama.js` | The 3D street in the footer |
